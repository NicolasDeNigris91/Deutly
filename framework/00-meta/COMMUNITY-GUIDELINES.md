### 1.4 Cohort-Tracking-System (Vision)

Lerner können ihren PROGRESS.md in einem **separaten Repo** veröffentlichen:
- `username/Erkenntnisprojekt-Cohort-2026` (Beispiel).
- PROGRESS.md transparent zeigt Modul-Abschluss.
- Optional: Aufsätze + Übersetzungen + Vortrags-Aufnahmen.

**Vorteile**:
- Soziale Accountability.
- Peer-Vergleich + Solidarität.
- Mentor-Sichtbarkeit für externe Mentoren.
- Empirische Daten für Framework-Iteration.

**Privacy**: opt-in; private Repos möglich + Pseudonymisierung empfohlen.

## 2. Verhaltens-Richtlinien

### 2.1 Grundprinzipien (cf. CODE_OF_CONDUCT.md)

- **Intellektueller Fokus**: Comunidade dient L2-Erwerb, nicht Politik / Religion / Selbstdarstellung außer relevant.
- **Rigor über Brand**: technische Korrektheit > PR / Selbstmarketing.
- **Honestidade über Niveau**: ehrlich kommunizieren, was man kann + was nicht; keine inflated claims.
- **PT/DE/EN bevorzugt**: Diskussion in einer dieser Sprachen; andere Sprachen erlaubt aber weniger Reichweite.
- **Respekt**: keine Polemik, keine ad hominem; technische Kritik OK.

### 2.2 Verbotene Verhalten

- Plagiat (eigene Arbeit als fremde ausgeben oder umgekehrt).
- Spam / kommerzielle Werbung ohne Genehmigung.
- Belästigung / Diskriminierung (Geschlecht, Herkunft, Sexualität, Religion, etc.).
- Politische Polemik außer thematisch relevant.
- AI-generierte Texte als eigene ausgeben (cf. MENTOR §0 Modus C-Limits).

### 2.3 Mentoring-Konventionen

Wenn Sie Peer-Mentoring anbieten:
- Klar deklarieren: ehrenamtlich oder bezahlt.
- Loop der Verfeinerung anwenden (cf. MENTOR §1).
- Nicht fremde Aufsätze schreiben (Output-Hypothesis verletzen).
- Anti-Burlung-Tabelle befolgen (MENTOR §8).

### 2.4 Aufsatz-Feedback-Konventionen

Wenn Sie Feedback auf fremde Aufsätze geben:
- Konstruktiv-kritisch (nicht polemisch).
- Klassifiziert (BLOCKING > MAJOR > NIT; cf. MENTOR §1).
- Mit Begründung (warum diese Korrektur?).
- Mit Verweis auf Stage-spezifische Erwartungen.

## 3. Lesegruppen + Aktivitäten

### 3.1 Lesegruppen

**Wöchentliche / 14-tägliche Lesegruppen** zu kanonischen Texten:

- **Adorno-Lesekreis** — *Minima Moralia* aphorism by aphorism.
- **Habermas-Lesekreis** — *TkH* Kapitel by Kapitel.
- **Hegel-Lesekreis** — *Phänomenologie* Sub-Sektion by Sub-Sektion.
- **Heidegger-Lesekreis** — *Sein und Zeit* §§ by §§.
- **FAZ-Feuilleton-Lesekreis** — wöchentlicher Artikel.

**Format**: 60-90 min via Voice-Chat (Discord) oder Jitsi; Moderator wechselt.

### 3.2 Cohort-Programme

**Stage-spezifische Cohorts** (geplant ab v3.5+):

- **Stage 1 Cohort** — 6 Monate; 8-12 Lerner; wöchentliche Treffen.
- **Stage 2 Cohort** — 4 Monate; 8-12 Lerner.
- **Stage 3 Cohort** — 4 Monate; 6-10 Lerner.
- **CAPSTONE-X Cohort** — projektorientiert; 3-6 Lerner; eigener Begriff jeder Lerner.

**Anmeldung**: via GitHub Discussions oder Discord-Anfrage. Begrenzte Plätze.

### 3.3 Konferenz / Workshop online (vision v3.5+)

**Jährliche FATHOM-Deutsch Online-Konferenz**:
- 1-2 Tage; via Zoom/Jitsi.
- Vorträge von Lernenden + externen Mentoren.
- Workshops zu Stage-spezifischen Themen.
- Open zu allen Lernenden.

## 4. Beiträge zur Framework-Entwicklung

### 4.1 Issue-Reporting

Bugs, Tippfehler, broken links: GitHub Issues.

Format:
- Klar beschreiben (welche Datei? welche Zeile? was falsch?).
- Korrektur-Vorschlag wenn möglich.
- Verweis auf Quelle bei Quellenkritik (Eisenberg / Helbig-Buscha / etc.).

### 4.2 Pull Requests

Korrektur-PRs willkommen. Workflow:
1. Fork des Repo.
2. Feature-Branch.
3. Änderungen mit klaren Commit-Messages.
4. PR mit Beschreibung + Verweis auf Issue (wenn vorhanden).
5. Review durch Mantenedor.
6. Merge.

**Wichtig**: cf. PULL_REQUEST_TEMPLATE.md — keine AI co-author trailers; CC BY-NC 4.0 respektieren.

### 4.3 Worked Examples

Lerner können eigene CAPSTONE-X-Exemplares (für andere Begriffe als Aufklärung) als PR einreichen:
- CAPSTONE-1-Bildung-EXEMPLAR
- CAPSTONE-2-Geist-EXEMPLAR
- etc.

**Standard**: cf. CAPSTONE-1+2+3+4+5-AUFKLAERUNG-EXEMPLAR als methodische Modelle.

## 6. Mantenedor-Verantwortung

### 6.1 Antwort-Erwartung

Mantenedor (aktuell: Nicolas de Nigris) verpflichtet sich zu:
- **Issues**: Antwort innerhalb 14 Tagen.
- **Pull Requests**: Review innerhalb 30 Tagen.
- **Discord/Matrix-Anfragen**: Antwort innerhalb 7 Tagen wenn möglich.
- **Lesegruppen-Moderation**: regelmäßige Teilnahme; kann aber rotiert werden.

### 6.2 Co-Mantenedoren

Wenn Comunidade wächst (>200 aktive Mitglieder), wird Mantenedor-Team erweitert:
- Co-Mantenedoren mit Schreib-Rechten.
- Spezialisierten Mantenedoren (Stage 6 Track A / B / C / D Verantwortliche).
- Übersetzungs-Mantenedoren (DE / EN / ES / FR).

Auswahl-Kriterien: nachweisliche Stage-5-Reife + sustained Comunidade-Engagement (6+ Monate).

## 7. Krisensituationen

### 7.1 Bei Konflikten

- Erste Instanz: direkter Dialog zwischen Beteiligten.
- Zweite Instanz: Moderation durch Mantenedor.
- Dritte Instanz: temporärer Bann + Diskussion über Verhalten.
- Vierte Instanz: dauerhafter Bann (selten; nur bei wiederholten Verstößen).

### 7.2 Bei Plagiats-Verdacht

- Substantielle Belege erforderlich.
- Diskussion mit Beteiligten.
- Bei nachgewiesenem Plagiat: Bann + öffentliche Klarstellung.

### 7.3 Bei Mantenedor-Verschwinden

Falls Mantenedor langfristig nicht erreichbar (>3 Monate ohne Antwort):
- Co-Mantenedoren übernehmen.
- Falls keine Co-Mantenedoren: Comunidade kann Repo forken + neue Mantainer-Struktur etablieren.
- Der ursprüngliche Repo bleibt als historische Referenz.
